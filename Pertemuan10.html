00 · Pengenalan

Apa itu Docker?

Docker adalah platform open source untuk membangun (build), membagikan (share), dan menjalankan (run) aplikasi di dalam container, yaitu paket ringan berisi aplikasi beserta seluruh dependensinya, sehingga berjalan sama di laptop, server, maupun cloud.

Docker EngineDocker DesktopDocker HubDocker Compose
🐳 Sejarah singkat
2013Solomon Hykes (perusahaan dotCloud) merilis Docker sebagai open source di PyCon.
2015Docker ikut mendirikan Open Container Initiative (OCI) untuk standar format image & runtime.
2017Runtime containerd didonasikan ke CNCF, dan proyek Moby diluncurkan.
2019Bisnis Docker Enterprise dijual ke Mirantis; Docker fokus ke developer (Desktop & Hub).
2025–26Fokus baru: AI. Sandboxes untuk AI agent, Model Runner (LLM lokal), MCP Gateway, dan Hardened Images.

01 · Masalah

"Di laptop saya jalan kok, Pak!" 😅

Aplikasi bergantung pada versi bahasa, library, dan konfigurasi OS. Begitu pindah komputer, salah satunya berbeda, dan aplikasi pun gagal. Bandingkan dua skenario di bawah.

Setiap lingkungan memiliki versi berbeda → bug yang sulit dilacak, waktu setup lama, dan deployment yang menegangkan.
Aplikasi beserta seluruh dependensinya dikemas dalam satu image. Image yang sama dijalankan di mana pun → hasilnya identik.
🚢

Analogi peti kemas: sebelum ada kontainer standar, kapal memuat barang berbagai bentuk, sehingga bongkar-muatnya lambat. Peti kemas berukuran standar dapat diangkut kapal, truk, maupun kereta tanpa dibongkar. Docker melakukan hal yang sama untuk software.

02 · Konsep

Virtual Machine vs Container

VM memvirtualisasi hardware (setiap VM membawa OS lengkap). Container memvirtualisasi sistem operasi (semua container berbagi kernel host), sehingga jauh lebih ringan.

04 · Konsep Inti

Image vs Container

Image adalah cetakan (template read-only). Container adalah image yang sedang dijalankan. Satu image dapat menghasilkan banyak container, seperti satu resep kue menghasilkan banyak kue.

🗂 Image nginx:latest

Tersusun dari layer bertumpuk (read-only), di-cache dan dipakai bersama.

Layer 1 · debian base
Layer 2 · install nginx
Layer 3 · config default
Layer 4 · entrypoint script

📦 Containers dari image yang sama

Setiap container mendapat layer tulis tipis miliknya sendiri, jadi perubahan di satu container tidak memengaruhi yang lain.

Belum ada container. Klik tombol di kiri.
🍰 Analogi OOP: Image = class, Container = object. docker run ≈ new.

07 · Dockerfile

Membuat image sendiri dengan Dockerfile

Setiap instruksi menambah layer. Docker meng-cache layer yang tidak berubah, sehingga build ulang jauh lebih cepat. Itulah alasan package.json di-COPY lebih dulu.

08 · Jaringan

Port mapping: -p HOST:CONTAINER

Container memiliki jaringan terisolasi. Agar dapat diakses dari browser, port container harus "diteruskan" ke port di komputer host.

💻
Browser di Host
:8080
http://localhost:8080
📦
Container
:80
aplikasi mendengar di :80
Coba: ubah container port menjadi 8080, atau host port menjadi 3306 (sudah dipakai MySQL lokal).
09 · Storage

Volume: agar data tidak hilang

Container bersifat sementara. Ketika dihapus, semua data di dalamnya ikut hilang. Volume menyimpan data di luar container. Jalankan 4 langkah berikut dengan dan tanpa volume.

Tanpa volumeDengan volume
📦 container: -
/var/lib/mysql
🛢 volume
dbdata
Perintah terkait: docker volume create dbdata · docker volume ls · docker volume inspect dbdata · bind mount: -v ./src:/app

📝 Tugas Praktikum

Kontainerisasi sebuah aplikasi web sederhana (bebas: Node.js, PHP, atau Python). Centang yang sudah selesai:

✅ Best Practice

Gunakan image resmi dan tag spesifik (node:20-alpine, bukan latest) di produksi.
Pilih image kecil (alpine/slim) dan manfaatkan urutan layer untuk cache.
Satu container = satu proses/tanggung jawab.
Simpan data di volume, rahasia di environment variable/secret, bukan di image.
